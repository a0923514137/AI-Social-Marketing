# GPT 客戶買斷交付技能

## 觸發條件
使用者要求「買斷交付」、「客戶打包」或「使用買斷交付技能」。適用於社群行銷、LINE、選股、POS、網站、剪輯及其他應用。依實際架構選擇服務，不強制使用 Supabase 或 Meta。

## 執行流程
1. 盤點實際原始碼、依賴、資料庫、外部服務、已驗收及未完成項目。不得將推測視為已完成。
2. 建立獨立 GitHub 交付分支；預設只更新 GitHub，不部署、不修改既有系統、不建立客戶帳號、不重新打包，除非使用者要求。
3. 移除原業主識別資料、真實金鑰、客戶資料、私人網址及無關模組；保留必要程式、版本鎖定及授權聲明。提供空白設定範本及必要的資料庫初始化腳本。
4. 建立 START-HERE.md、README.md、docs/CUSTOMER-SETUP.zh-TW.md、docs/ACCEPTANCE.md。依實際服務列出申請入口、設定位置、必要權限、費用可能性、安裝、停用、更新及故障排除。
5. START-HERE.md 必須包含可直接複製給 GPT 的安裝指令（見下方範本），並依應用調整服務與驗收順序。
6. 提供靜態檢查、測試與安全檢查方式；區分原始碼檢查、資料庫驗收、實際端到端驗收。未完成項目明列 NO_GO，不宣稱正式可用。
7. 只有使用者要求打包時，才從指定 GitHub commit 建立 ZIP，排除真實金鑰、資料、快取及無關檔案，提供 SHA256 與來源 commit；實際核對後才宣告 PASS。

## GPT 安裝指令範本（寫入 START-HERE.md）
你是我的應用程式安裝助手。我不是工程師。先閱讀我上傳的完整 ZIP、README、設定範本、安裝及驗收文件，以實際檔案為準。使用繁體中文，每次只提供一個可執行步驟，等待我回覆 33 或截圖才繼續，不重複已完成事項。

依序引導我申請自己的 GitHub 及本應用實際需要的服務帳號、建立私人專案、設定資料庫與權限、設定金鑰、部署及串接。不得要求我將真實金鑰貼到聊天中或提交原始碼；引導我在服務的 Secrets 或安全設定介面輸入。不得使用供應商既有帳號、資料庫或正式環境。先依最新官方文件確認必要設定與費用，取得我的確認才執行有副作用的操作。預設關閉對外發送、正式付款及其他高風險功能（如適用）。

逐步依驗收文件測試；失敗時依日誌修正，不重複相同失敗步驟。若無法直接操作外部服務，提供網頁步驟或可複製指令，不得宣稱已操作。實際驗收成功且取得我的明確同意後才啟用。最後整理安裝結果、未完成事項、維護、停用及金鑰輪替方式。

## 交付標準
客戶下載 GitHub ZIP → 上傳自己的 ChatGPT → 複製 START-HERE.md 指令 → 自行申請必要服務 → GPT 引導設定與串接 → 驗收後啟用。

每次回報實際 GitHub 更新檔案、commit、驗收結果與阻礙。不得把尚未安裝或測試的技能稱為已安裝或已驗收。

# R130-08 YouTube 留言回覆預覽

沿用 `social-worker` 的 POST 入口和 `x-social-scheduler-key` 驗證。請求內容為 `{"task":"youtube_poll","mode":"preview"}`。預定節奏為 `*/5 * * * *`，由 Staging 驗收後另行啟用。

- 使用 `YOUTUBE_CHANNEL_ID`、`YOUTUBE_CLIENT_ID`、`YOUTUBE_CLIENT_SECRET` 和 `YOUTUBE_REFRESH_TOKEN`。OAuth 刷新後以 `channels.list(mine=true)` 驗證頻道身分。
- 唯讀共用現有 Instagram 固定範本 `default_ai`、`ep03_video_edit` 和 `ep08_automation`。系統沿用 AI 範本。同一則留言依剪片、自動化、AI／系統的順序採用第一個命中。
- `YOUTUBE_REPLY_BASELINE_AT` 使用含時區的 ISO 8601 時間。未設定時以當次請求開始時間為基準。只考慮基準之後發布的頂層留言，略過本人、重複 ID、已有回覆和無法回覆的留言。
- 每次預覽最多讀取五頁，仍有後續頁時回傳 `partial`。同一個暖執行實例每天最多發出 2,000 次 YouTube 讀取請求。遇到 Google 每日配額錯誤會停讀至太平洋時區換日，限流時回傳 HTTP 429。401 時更新 Token 後重試一次。
- 預覽最多列出 150 則候選。啟用對外發送前須以持久化交易實作跨執行個體的每日 150 則上限與留言認領，並驗證逾時後的去重處理。

## 驗收結果

- Deno 測試 19 項通過，涵蓋新增的 YouTube Mock 及既有 social-worker、Instagram patrol 測試。
- 使用本機 OAuth 和從 Staging 唯讀 SQL 取得的三筆範本執行 adapter。實際 YouTube API 讀取 37 則，37 則均因歷史基準略過，候選及發送均為 0。
- Staging Edge Function 部署及排程啟用留待下一階段。Production 維持 NO_GO。
